# 命令与交互（Minecraft 26.3）

## 参考与取舍

2026-10-27 查阅了两个项目的一手使用说明：

- [Textile Backup 的 Usage](https://github.com/Szum123321/textile_backup/wiki/Usage)提供命名/注释备份、列表、恢复、清理和单独删除等操作。这说明备份需要可发现、可辨识的入口；EDB 增加帮助、列表、详情与名称补全。
- [FTB Backups 3 的配置文档](https://docs.feed-the-beast.com/mod-docs/mods/suite/Backups-3/config/)明确区分聊天/状态栏通知、进度面板和通知接收者。EDB 在开始、结束和失败时说明整服状态，重复进度使用动作栏及操作者私有反馈。

这些项目面向完整存档备份。EDB 的区域定义和恢复确认流程，是针对本项目的操作范围设计的：定义与快照分开，预览先显示被覆盖的维度和边界。此次未加入定时备份、自动清理、保留策略、白名单或客户端 GUI；不增加额外 UI 模组依赖。

## 一次完整操作

```text
/edb region create factory 0 0 99 99
/edb region info factory
/edb backup before_change region factory
/edb list
/edb info before_change
/edb restore before_change
/edb restore before_change confirm
```

创建的 `factory` 覆盖当前维度 100×100 个区块的整个高度，允许包含未加载、未生成的位置。只有执行备份/恢复时才进入维护；定义管理、补全、列表和预览均不加载区块。

`restore` 首先异步读取清单，检查世界标识、Minecraft 版本、数据版本与范围，然后显示影响。预览不会暂停模拟，也不会完整读取所有区块数据。只有同一玩家 UUID（非实体命令源按名称、维度、位置区分）在预览完成后 60 秒内确认，才会请求恢复。这个期限使用真实时间，不受 tick 冻结影响。

确认只消费一次；名称不匹配、到期、取消或配置重载后必须重新预览。取消一个尚未完成的异步预览也有效，旧回调不会重新生成授权。进入维护时再次比较预览清单，清单有变化则拒绝，随后仍按原流程完整校验数据，再开始卸载和覆盖。

## 命令表

| 命令 | 行为 |
| --- | --- |
| `/edb`、`/edb help` | 显示用法、权限要求和坐标单位 |
| `/edb region create <区域名> <x1> <z1> <x2> <z2>` | 当前命令维度创建定义；重名拒绝 |
| `/edb region update <区域名> <x1> <z1> <x2> <z2>` | 明确修改已有定义，也更新为当前命令维度 |
| `/edb region list [页码]` | 按名称排序，每页 8 个 |
| `/edb region info <区域名>` | 显示维度、闭区间区块边界、数量 |
| `/edb region remove <区域名>` | 只删除定义，已有备份保留 |
| `/edb backup <备份名> region <区域名>` | 使用定义的维度和范围创建独立快照 |
| `/edb backup <备份名> <x1> <z1> <x2> <z2>` | 保留直接坐标入口，使用当前命令维度 |
| `/edb list [页码]` | 完整发布的备份，每页 8 个；不显示 `.partial` |
| `/edb info <备份名>` | 清单详情，包含时间、范围和捕获时世界刻 |
| `/edb restore <备份名>` | 预览影响并生成限时确认 |
| `/edb restore <备份名> confirm` | 消费本人的确认，排队恢复 |
| `/edb cancel` | 取消本人的待确认恢复，不中断已排队/执行的操作 |
| `/edb status` | 查询排队/维护阶段和耗时；空闲时附上次结果 |
| `/edb reload` | OP 4 重载权限配置，刷新在线玩家命令树并清除待确认恢复 |

区域和备份名称独立，均为 1–64 个英文字母、数字、`_` 或 `-`。已有备份不可覆盖。区块坐标包括两端，允许反向指定端点并自动归一化。负区块坐标是向下取整，例如方块 X=-1 位于区块 X=-1。用 F3 的区块坐标确定边界；每次上限仍为 65,536 区块。

跨维度可用 `/execute in minecraft:the_nether run edb region create factory_nether ...`。修改定义只影响以后的备份，旧快照永远使用自身清单的边界和维度。

## 权限与文件

`config/extraordinarydynamicbackup.json` 的 `permissionLevel` 默认为 `3`，接受整数 `0–4`。统一保护整个 EDB 命令树，避免低权限用户通过区域修改间接影响备份。设为 `0` 将允许所有玩家查看、管理区域、备份及确认恢复；`reload` 另固定要求 OP 4。重载非法文件时旧值继续生效，启动时非法配置会明确报错而不会静默降低权限。

`<世界>/edb/regions.json` 独立于备份存储，最多 1,024 个定义，最大 1 MiB；写入临时文件后原子替换。损坏、重名创建或保存失败不会被当作成功。目录查询、定义读写和清单读取共用独立的有界串行 IO 队列，不扫描备份中所有区块，也不阻塞服务器线程等待磁盘。

新快照在原有格式 1 的清单中增加可选字段 `created_at`（UTC epoch 毫秒）。旧快照仍可读取，时间显示“旧格式未记录”；原有数据路径不迁移。预览中的世界刻只是捕获信息，恢复不回退全局时间。

## 提示与维护期间

提示由服务端直接生成中文文本，普通客户端也能显示；底层错误保留原始异常内容，便于定位日志。聊天提示可点击填入命令，需要按回车提交。成功响应不再借用管理员广播发送每条查询和进度。

全服聊天收到开始、结束或失败提示，因为暂停影响全服。每五秒向操作者发送阶段与耗时，并向在线玩家动作栏发送阶段提示；等待阶段不显示伪造的进度百分比。区块计数只属于当前阶段，阶段切换会重新计数。

维护期间仍只放行直接的 `edb status` 和原版 `stop`，其他命令解释当前暂停状态并提示查询。`stop` 必须满足原版 OP 4 权限，正常维护时排队等操作完成后停服；恢复失败并保持暂停时允许 OP 4 停服。不能安全中断已经开始的覆盖，所以没有维护中取消恢复的入口。

恢复前真实玩家必须离开选区；真实玩家背包和世界级状态不属于区域快照。已适配的 Carpet 假人继续使用已有恢复机制。覆盖阶段失败会明确提示“模拟保持暂停”，不会误报恢复成功或自动继续游戏。

## 验证

`CommandInteractionProbe` 接入现有的真实服务器顺序 GameTest，覆盖 0–4 权限矩阵、默认 OP 3、OP 2 实际命令拒绝、非法重载保留旧权限、区域定义持久化/重名/损坏文件保护、旧清单兼容、确认的一次性/到期/来源/异步取消、预览清单变化拒绝、命令驱动的区域备份与恢复。原有测试另在维护中通过实际命令拦截器执行 OP 3 的 `stop`，确认不会排队停服。

原有加载/未加载区块、实体、光照、POI、假人与车辆、模组组合和压力测试继续保留。聊天组件、消息内容及命令状态经过服务端测试；真实客户端的点击和动作栏视觉效果尚未人工验收。

本轮测试结果及发现并修复的 ECO 并发借用问题见[回归报告](../tests/results/26.3-command-ux.md)。
