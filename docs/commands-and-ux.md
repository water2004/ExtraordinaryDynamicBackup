# 命令与交互（Minecraft 26.3）

## 交互约定

以区域为管理单位，每个区域有自己的递增备份编号。参考用户指定的 [Prime Backup（!!pb）](https://tisunion.github.io/PrimeBackup/feature/backup_display/)：使用 `make / list / show / back / delete`，列表显示编号、创建时间、备注和操作按钮；恢复和删除先预览，再确认。创建时可直接添加[备注](https://tisunion.github.io/PrimeBackup/feature/backup_create/)，不要求为每个备份取名字。

命令统一在 `/edb region <区域>` 下。删除一个区域会删除其下所有备份及未完成目录。旧命令树不保留别名，按用户要求不提供旧格式迁移。

## 一次完整操作

```text
/edb region create factory -60 -9 -31 14
/edb region factory make 改造前
/edb region factory list
/edb region factory show 1
/edb region factory back 1
/edb confirm
```

输入的是**精确方块 X/Z 坐标**，包括两端，覆盖全部高度。上述例子覆盖方块 X `-60..-31`、Z `-9..14`，涉及区块 `(-4,-1)..(-2,0)`，共 6 个；边界区块内选区外的当前内容保留。创建、更新、详情和恢复预览显示精确方块范围及涉及的区块范围。

六个坐标表示 XYZ 长方体，例如 `/edb region create room -60 10 -9 -31 50 14`；`update` 同样接受四个或六个整数。Y 与维度实际高度必须有交集。范围可反向输入，保存时各轴分别归一化。

负数使用向下取整：方块 `-1` 属于区块 `-1`，不是 `0`。两端顺序可以反向。100×100 区块的例子是方块 `0 0 1599 1599`。每次上限仍为 65,536 区块；定义、列表、补全和预览不加载区块。

区域使用创建/更新命令所在维度。跨维度可用 `/execute in minecraft:the_nether run edb region create factory_nether ...`。更新区域只影响以后的备份；已有备份始终按其自身保存的维度和范围恢复。

## 命令表

| 命令 | 行为 |
| --- | --- |
| `/edb`、`/edb help` | 显示区域层级用法、权限与坐标单位 |
| `/edb region list [页]` | 列出区域；也可直接 `/edb region` |
| `/edb region create <区域> <x1> <z1> <x2> <z2>` | 按方块坐标创建区域；重名拒绝 |
| `/edb region create <区域> <x1> <y1> <z1> <x2> <y2> <z2>` | 创建精确 XYZ 长方体 |
| `/edb region <区域>`、`list [页]` | 本区域备份，按创建时间倒序，每页 8 项 |
| `/edb region <区域> show` | 区域维度与实际范围 |
| `/edb region <区域> update <x1> <z1> <x2> <z2>` | 用方块坐标修改以后备份的范围 |
| `/edb region <区域> update <x1> <y1> <z1> <x2> <y2> <z2>` | 修改为指定 XYZ 长方体 |
| `/edb region <区域> make [备注]` | 自动分配编号并创建备份；允许多词中文备注 |
| `/edb region <区域> show <编号>` | 创建时间、备注、原始范围和捕获时世界刻 |
| `/edb region <区域> comment <编号> [新备注]` | 修改备注；不填则清空，不改变创建时间 |
| `/edb region <区域> back <编号>` | 预览恢复，显示覆盖范围及整服暂停影响 |
| `/edb region <区域> delete <编号>` | 预览永久删除本区域的指定备份 |
| `/edb region <区域> delete` | 预览删除整个区域及其全部备份，显示数量 |
| `/edb confirm` | 执行本人最后一次仍有效的预览 |
| `/edb abort` | 取消待确认操作，不中断已经开始的操作 |
| `/edb status` | 维护进度、目录管理状态或上次结果 |
| `/edb reload` | OP 4 重载权限配置、刷新命令树并取消待确认操作 |

区域名为 1–64 个英文字母、数字、`_` 或 `-`。与固定命令同名的区域 `create`、`list` 可用引号访问，例如 `/edb region "list" make`。编号在同一个区域内递增；删除单个备份不复用编号，失败或取消的分配可能留下空号，不表示备份丢失。不同区域可以各有 `#1`，每处提示都带区域名。

列表每行形如：

```text
[#3] 2026-10-27 23:00:00 +08:00 | 改造前 [详情] [恢复] [删除]
```

时间使用服务器系统时区，并明确显示偏移。无备注显示“无备注”；备注最多 256 个字符，拒绝控制字符。聊天按钮把命令填入输入框，需要按回车提交；不会点击即删除。编号补全仅列出当前区域的备份。损坏清单的编号目录仍显示错误并提供删除入口，未发布的 `.partial` 不列为备份。

## 确认与并发

恢复、单删和删区域共用 60 秒的一次性确认。每个操作者只能保留最后一个预览，玩家按 UUID 隔离，非实体命令源按名称、维度、位置隔离。期限按真实时间计算。取消、重载、过期及任意目录写操作都会使待确认失效，旧异步预览回调也不能重新授权。

恢复进入维护时再次比较备份清单，随后完整校验数据；备注或其他清单信息变化也会拒绝旧预览。删除单个备份再次比较预览时的清单状态；删除区域再次比较区域范围和全部子目录名单。预览本身不暂停世界。

所有目录写操作先在主线程取得管理预留，在有界串行 IO 队列完成后，由主线程释放。备份/恢复排队或执行时，不能删除、修改定义或备注；目录修改进行时也不能排队备份/恢复。创建备份的编号分配与请求入队在同一预留流程中衔接，避免区域刚被删除却仍发布出一个快照。

文件清理在后台进行，不暂停世界，也不把整棵目录放到主线程删除。区域目录清理成功后才删除定义。磁盘失败会明确报错，可能已删除部分文件；保留定义便于重新预览重试，不把失败报为成功。管理目录拒绝符号链接、联接或越界路径，删除其他区域不在本次操作范围内。

## 权限、文件与维护提示

`config/extraordinarydynamicbackup.json` 的 `permissionLevel` 默认为 `3`，接受整数 `0–4`，统一控制整个命令树；`reload` 另固定要求 OP 4。非法重载保留旧权限。

```text
<世界>/edb/
  world-id.txt
  regions.json
  regions/<区域>/
    sequence.txt
    backups/<编号>/
      manifest.nbt
      runtime.nbt
      chunks/<x>_<z>.nbt
```

清单保存创建时间、备注和原始选区等信息。编号持久化使用临时文件加原子替换；备注也原子替换清单。删除区域包含其计数器、完整备份和未完成文件；不会修改当前世界。删除单个备份只清理一个编号目录。

备份和恢复仍从 tick 边界进入维护，整服模拟暂停、连接保持。全服聊天提示开始、完成和失败，每五秒向操作者与在线玩家动作栏发送阶段进度。真实玩家须离开本次涉及的区块；Carpet 假人会自动下线，选区内按备份重建，区外按临时保存的当前状态重建；真实玩家背包与世界全局状态不回退。边界区块按范围合并，实体以自身所在方块位置判定；跨边界乘坐树拒绝处理。精确恢复的状态范围及原版生物群系粒度限制见[实现说明](regional-backup-design.md)。已开始的覆盖不能安全中断，因此 `abort` 只取消待确认操作。

区域定义与快照均使用格式 2，保存精确边界；不迁移旧数据。

## 自动验证

`CommandInteractionProbe` 接入真实服务器顺序 GameTest，覆盖权限矩阵、默认 OP 3、非法配置、方块坐标负数换算、列表排序/时间/备注、独立区域编号、备注持久化、创建时间不变、编号不复用、原始范围恢复、单删、级联删除、取消与过期、陈旧预览拒绝、异步回调失效及目录预留互斥。

存储用例另验证损坏清单仍能删除、区域删除清理未完成目录、另一区域保持完整、越界路径拒绝，以及预览后目录改变时拒绝删除。原有加载/未加载区块、光照、实体、POI、假人与载具及模组压力测试继续保留。真实客户端按钮与动作栏视觉效果尚未人工验收。

`PreciseSelectionTests` 另外覆盖 XYZ/XZ 恢复、负数与区块/区段边界、选区外实体及容器内容保留、方块/流体计划刻、POI、光照、40 状态调色板、原版生物群系网格、方块事件、未加载边界与原本缺失的地形，以及边界当前缺失/仍在生成时的预检拒绝。

完整压力模式另外对 100×100 个有数据的未加载区块执行 Y=5..10 的 XYZ 备份/恢复，逐块解码方块状态，验证选区内 Stone、选区外当前 Gold、当前区块级元数据保留与无 holder 加载。Carpet 组合同时覆盖完整区块和限高选区的假人/多层载具往返。
