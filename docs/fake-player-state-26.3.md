# 26.3 区域回档中的 Carpet 假人

此功能只服务于区域备份／恢复，不增加服务器停服、重启后自动上线的驻留功能。假人不需要由用户手动离开；仍要求真实玩家离开受影响的区块。

## 两种状态

| 假人的位置 | 恢复来源 |
| --- | --- |
| 选区内，或 UUID 属于该备份中的假人 | 备份中的玩家与运行状态；备份后离开、下线的假人也会找回 |
| 选区外，但其自身或载具树会受边界区块卸载影响 | 本次操作临时保存的当前状态；不回退到备份时间 |
| 其他假人 | 保持在线 |

备份后新建的选区内假人会移除。跨精确选区边界的乘坐树仍拒绝拆分；应让整棵树处在同一侧。若根载具在卸载区块之外、普通实体乘客却在卸载区块内，也会在覆盖前拒绝，避免卸载部分乘客后丢失关系。受影响的树不能包含真实玩家。

## 源码核对与保存内容

对照本项目实际使用的 Mojang 26.3 源码：`LivingEntity`、`Player`、`ServerPlayer`、`ServerPlayerGameMode`、`ItemCooldowns`、`CombatTracker`、`PlayerList`，以及 Carpet 的 `EntityPlayerMPFake`、GCA 的 `FakePlayerResident`／`BotInfo`。

GCA 驻留保存的是重新生成假人的描述，包括位置、方向、模式、动作和执行器，再使用普通玩家数据。它不是整个运行中玩家对象的序列化。本适配继续使用 Carpet 的创建入口，但从备份提供玩家 NBT，并补充已核查的运行字段。

| 内容 | 保存与恢复方式 |
| --- | --- |
| UUID、背包、末影箱、生命、饥饿、经验、能力、模式、效果等 | 玩家 NBT；飞行等能力在登录初始化后再次应用 |
| 实体年龄、移动、姿态等已有补充字段 | `RuntimeStateCodec` 与实体 Mixin |
| ActionPack | 移动、潜行、疾跑、挖掘、使用冷却，以及每个动作的次数、间隔、剩余时间和完成状态 |
| 正在使用的物品 | 手、使用标记、剩余使用时间 |
| 物品冷却 | 组、开始／结束计数和内部 tick 计数一起恢复，保留剩余时间与冷却百分比 |
| 攻击与移动 | 攻击蓄力、换手计数、跳跃延迟、输入、游泳、鞘翅／旋转攻击、挥手动画进度等显式字段 |
| 伤害与战斗 | 伤害免疫计数、上次伤害、战斗记录、伤害类型／来源、攻击目标 UUID、动能攻击命中时间等 |
| 挖掘管理器 | 当前／延迟破坏标记、坐标、方向、起始计数、管理器内部 tick 与裂纹阶段 |
| 睡眠 | 床位置、睡眠计数和姿态；加载时暂不提供 `sleeping_pos`，避开普通登录的唤醒及草床拆除副作用，再恢复睡眠元数据 |
| 客户端选项 | 使用原版 `ClientInformation` 编解码保存主手、视距、语言等选项 |
| 载具 | 区域实体记录保存车辆树；玩家条目保存直接车辆 UUID 和座位，重建后恢复交错乘客顺序 |
| 已适配延迟任务 | 清理引用旧对象的 TIS／GCA 任务，再为新假人恢复剩余次数／延迟；不序列化任意 Runnable |

`HurtTime`、`DeathTime`、普通睡眠计时等本来已有 NBT；不能将它们误认为全部需要日常追踪。新增字段在维护屏障捕获和应用，不增加逐 tick 的全量假人状态镜像。原有特定模组队列挂钩仍用于识别其待执行任务。

以世界时间计量的时间戳保存相对年龄，恢复到当前世界时间；玩家和交互管理器自己的计数连同对应计时字段一起恢复。世界时间本身不会回退。

## 生命周期与文件职责

1. 完成快照和假人运行数据预检，保留旧假人在线状态直到预检通过。
2. 捕获区外假人当前状态；用独立、非持久化的 EDB 票据保留新旧玩家／载具所在区块。
3. 选区内及同 UUID 假人下线。再次静置，分批保存当前边界区块中的车辆树和其他区外内容。
4. 区外受影响假人下线，排空由下线产生的原版／NoTickVD 票据变更，再冻结和暂存 C2ME root tickets。
5. 按既有卸载、写入、刷新、重载流程替换区域。等待所需区块与实体加载完成。
6. 每维护帧最多创建一个假人，恢复动作／运行状态和载具关系；全部假人出现后重连战斗／钓鱼引用，并刷新睡眠统计。
7. 撤销本次 EDB 票据，不撤销用户的强加载票据。真实客户端正常同步；假人只重置连接位置缓存，避免同步传送再次改写头部朝向。

适配全部位于 `adaptors/carpet/`：

- `CarpetFakePlayerAdapter`：玩家 NBT、Carpet 创建／下线入口、ActionPack、物品使用、挂载。
- `CarpetPlayerRuntime`：显式的 26.3 运行字段、冷却、睡眠、客户端选项，以及覆盖前的 schema 检查。
- `CarpetCombatState`：战斗记录与实体引用的编解码，待所有假人上线后重连引用。
- `CarpetRestoreSession`：区外假人当前状态的临时保管、区块票据与加载等待。

选区内假人存放在快照的 `runtime.nbt`。区外当前假人条目仅保存在本次维护会话内存中，不混入历史备份；其当前车辆树随 `.merge-*` 边界记录暂存。假人运行条目使用 schema 1；缺失或不支持的条目在下线前拒绝，不提供旧假人格式迁移。

## 保证边界

这是对已列明状态和固定版本组合的恢复，不能称为任意假人对象的完整内存检查点。随机数、服务器全局状态、统计／进度数据库、任意 Scarpet 程序、第三方字段／脚本和未适配任务不随区域回退。已打开容器在操作开始时关闭。

指向区域外实体的历史引用，仅在实体仍可解析时重连；区域外实体已消失时不会据此复制或复活它。普通非玩家生物也没有因此获得全部 LivingEntity 瞬态字段。以上均不承诺未来逐 tick 重演。

临时状态不构成进程崩溃后的恢复日志。覆盖阶段失败仍保持模拟暂停；跨文件替换和假人重建没有崩溃原子性。正常完成才撤销临时票据。
