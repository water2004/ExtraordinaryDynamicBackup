## 新增交互检查

- 配置缺省为 OP 3；实际命令树的 0–4 权限矩阵；OP 2 不能备份、确认恢复或删除区域定义，reload 固定要求 OP 4。
- 非整数、字符串、布尔、null、越界权限重载被拒绝，原权限继续生效。
- 区域定义持久化、跨维度字段、反向端点归一化、100×100 大小；重名和损坏文件不会被覆盖。
- 命令驱动的“创建/修改区域 → 备份 → 删除定义 → 查看原快照 → 预览 → 取消 → 重新预览 → 确认恢复”。删除定义不删除快照。
- 预览既不排队也不执行恢复；确认绑定来源和备份名、一次消费、按真实时间到期；取消后迟到的异步预览不会重新授权。
- 清单与预览不一致时在 INIT 阶段拒绝，未应用恢复；缺少 `created_at` 的旧快照仍可读取。
- 维护期间 OP 3 的真实 `stop` 命令被拦截，不能排队停服。

## ECO 异常复现与修复验证

原版发布 JAR 的定向复现失败信息：

```text
ECO released its lease outside the owning frame lock: before=1, during=0
```

见 `.gradle/research/eco-lease-before-fix.log`。历史测试在持有 frame 锁时让另一线程关闭真实批次，记录到原代码先减少计数，再阻塞在回收锁上。加入实验补丁后测试通过；该补丁和专属探针现已移除。这不构成对 ECO 兼容 Async 的要求。

此前扩展测试和本轮初测曾出现“GameTest PASS，但停服抛异常”。该旧结果不能算正常停服通过。现在 Gradle 同时检查 `SERVER_STOPPED` 标记和停服异常日志，避免再把这类结果判为成功。

## 本轮附带修正与边界

区域 JSON 原子替换在 Windows 上实测遇到短暂 `AccessDeniedException`，现仅对该异常在目录 IO 线程做有限重试，保留原文件和原子替换，不把等待放到主线程。专用服每轮使用新世界，BlueMap 自动生成的测试 map 配置现同步指向本轮世界，避免误测旧世界。

真实客户端的点击和动作栏外观尚未人工验收；服务端消息、命令行为和状态流已验证。上述结果只覆盖锁定版本、配置和测试场景。
