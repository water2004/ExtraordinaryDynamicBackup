# Minecraft 26.3：区域管理与精确方块选区回归

日期：2026-10-28。区域管理提交 `218962b`，精确选区及测试提交 `35bf2f4`。Java 25 / Fabric，未增加旧格式迁移或 ECO/Async 并发补丁。

## 行为

- 按区域管理多个自动编号的备份，列表直接显示编号、创建时间、备注和操作入口。支持修改备注、单删，以及确认后删除区域和全部所属备份/未完成目录。
- 四个方块坐标表示精确 XZ 全高度，六个表示精确 XYZ 长方体，包括两端。保存区域与清单格式为 2，恢复使用备份自己的原始边界。
- 完整区块沿用直接替换；部分区块先分批暂存当前数据，再合并选区内容。方块实体、实体、POI、方块/流体计划刻及方块事件按精确位置处理。边界区段之外直接保留当前数据，完全包含的区段可直接复制调色板。
- 恢复前检查边界地形存在/生成状态和实体 UUID 冲突。保持有界批次、模拟暂停、异步 IO、原版 watchdog 与写入完成检查。

命令与操作范围见[交互文档](../../docs/commands-and-ux.md)，文件职责、原版数据粒度及限制见[实现说明](../../docs/regional-backup-design.md)。

## 最终验证

Windows x64，Microsoft OpenJDK 25.0.2，Minecraft 26.3，Fabric Loader 0.19.5，Fabric API 0.162.0+26.3。

| 环境 | 功能结果 | 停服 |
| --- | --- | --- |
| 纯 Fabric，最终 `build`（内含真实 GameTest） | 全部 2 个必需测试通过 | 生命周期标记 PASS；Gradle 成功 |
| lock 中全部 31 项依赖，同进程专用服 | `edb-test-result.txt=PASS`；原有及新增完整压力流程完成 | `edb-shutdown-result.txt=PASS`；Gradle 成功 |

专用服为独立新世界、loopback 随机端口，`max-tick-time=10000`。固定依赖见 [lock](../compatibility-lock.json) 和 [profile](26.3-precise-regions-dedicated.profile.txt)，包括 Carpet/additions、Lithium、VMP、C2ME、ECO alpha.12、Async、ServerCore、Servux、ScalableLux、地图与语音等。ECO 原生 FFM 后端实际启用，Async 并行实体与后台刷怪启用，C2ME gcFree serializer 开启。上游并未承诺 ECO 与 Async 的全面兼容，本轮只记录该固定组合的结果。

覆盖的断言：

- 命令权限、备注和时间列表、倒序分页、跨区域编号隔离、备注持久化及创建时间不变、编号不复用、陈旧/取消/过期确认拒绝、管理与维护的互斥。
- 区域删除同时清理完整与未完成文件；单删不影响其他备份/区域；损坏清单仍可删除。四/六坐标命令和 XYZ 定义重读后边界不变。
- XYZ 反向坐标、负数、X/Z 区块边界与 Y 区段边界，选区内箱子/实体/POI/光照恢复，同区块外部当前状态保留。
- 方块与流体计划刻的类型、剩余延迟、优先级；方块事件按 Y 边界筛选。40 状态 packed palette 用原版 Codec 解码后逐方块比较；生物群系逐个原版网格核对。
- 未加载边界恢复不产生 holder，原本缺失位置只在选中部分恢复为空气，保留区块其他位置；当前边界缺失与 protochunk 在覆盖前拒绝。离线边界实体 UUID 冲突拒绝。
- Carpet 假人完整区块和限高 XYZ 两套往返：ActionPack、使用进度、GCA 延迟任务、共享船、多层载具、与普通乘客交错的座位顺序。
- 维护期间世界刻和模组 tick 回调不推进，连接维护不随 IO 轮询加速；恢复后 10 个游戏 tick 实测 499 ms。

## 10,000 区块专项

[原始 CSV](26.3-precise-regions-dedicated.csv)：

| 场景 | 备份 | 恢复 |
| --- | ---: | ---: |
| 256 已加载区块、1,024 实体，5 轮平均 | 580.8 ms | 529.0 ms |
| 10,000 个有数据的未加载完整区块 | 18,180 ms | 8,164 ms |
| 同等规模，精确 XYZ 的 Y=5..10 合并 | 19,303 ms | 34,263 ms |

XYZ 场景使用 100×100 个未加载 FULL 区块：备份模板为 Stone，之后改成 Gold，再只恢复 Y=5..10。逐块用原版 Codec 解码，检查选中层为 Stone、同区段未选中高度及其他区段仍为 Gold、当前区块级自定义标记仍为 -1，并确认未加载地形。恢复耗时包含预检、当前边界暂存、合并、写入/刷新及临时目录清理。

CSV 所列压力操作中最长维护帧为 11 ms，XYZ 恢复为 5 ms；仅为本机观测值，8 ms 仍是不能抢占单次调用的软预算。压力模板规则、压缩率较高，不能据此推断任意生电存档耗时；没有模拟 10,000 个已加载高密度实体区块或真实多人网络负载。

## 测试期间修正与边界

测试曾发现：地下测试牛受到窒息伤害、旧版 `Name` 调色板测试数据不符合 26.3 编码，以及旧压力用例把一个区块坐标的数据直接写到另一个位置。这些已分别修正测试环境、使用实际 26.3 编码并纠正坐标，没有关闭相应检查。

新增 10,000 XYZ 场景的第一次运行在恢复完成后的验证阶段触发 watchdog。线程转储保存在本机；随后将批量验证解码移到后台，只在主线程读取 holder 状态和推进测试，重跑通过。最终生产 watchdog 仍为 10 秒，没有增加时间戳豁免或提高阈值。该失败日志保留为 `.gradle/research/precise-10000-dedicated.log`，不算通过结果。

最终日志中仍有故意构造的错误拒绝、C2ME 存储失败探针，以及既有 Windows 性能计数器、Mixin audit 已加载类消息和 spark 统计等待提示；没有 `Exception stopping the server` 或旧 ECO 碰撞表借用异常。不将“日志零 ERROR”作为本轮结论。

精确边界的部分区块须为 FULL 地形；生物群系仅有原版 4×4×4 网格粒度，跨边界网格保留当前值。结构/混合地形等区块级生成元数据在部分合并时保留当前值。实体按位置选取，跨界乘坐树拒绝。真实玩家及选区外假人须离开涉及区块；光照、邻居和后续正常模拟仍可跨边界传播。
