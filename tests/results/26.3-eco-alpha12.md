# ECO alpha.12 与 Async 合装复测

日期：2026-10-27。EDB 代码为 `e8f6af1`，包含 `67a3b24` 的维护等待优化，不含此前已撤销的 ECO 并发补丁或专属内部探针。本轮只更新测试依赖与记录，没有修改 EDB 生产代码。

## 版本与上游改动

使用 [ECO 官方 alpha.12 Release](https://github.com/water2004/EntityCollisionOptimizer/releases/tag/v1.0.0-alpha.12) 的 `entity_collision_optimizer-1.0.0-mc26.3-alpha.12.jar`，不是本地修改版。下载文件 SHA-256 与 GitHub 发布资产 digest 一致：

`c1080fa959fd0632760a1ba8055c4fae7068fe1c00bedefdb181bb49b5492795`

核对 [alpha.11 → alpha.12 源码差异](https://github.com/water2004/EntityCollisionOptimizer/compare/v1.0.0-alpha.11...v1.0.0-alpha.12)：`PushBatch.close()` 的借用释放与回收，以及 `applyNativeRun()` 的行定位与原生调用，现在持有所属 `LevelCollisionFrame` 的锁。相关修复为 `7cdf7f9dbbe9d7f87017006d36f0eed2e0287600`，发布版本提交为 `ff59ec02420ee5ffaf72ed1df2c0ea9aa908ff17`。上游明确保留“不保证与 Async 的兼容性和性能收益”的边界。

运行环境：Windows x64、Microsoft OpenJDK 25.0.2、Minecraft 26.3、Fabric Loader 0.19.5、Fabric API 0.162.0+26.3。Async 为 `0.2.5+alpha-26.3`，C2ME 为 `0.4.2-alpha.0.106+26.3`；其余依赖见 [lock 文件](../compatibility-lock.json)。

两次测试均启用 ECO FFM 原生后端、Async 并行实体 tick 与后台刷怪：`disabled=false`、`enableAsyncSpawn=true`、`maxThreads=-1`。`enableAsyncRandomTicks=false`，同步实体列表保持 TNT、经验球与物品，不包含压力场景的牛。C2ME `gcFreeChunkSerializer=true`。没有通过禁用 Async 或 ECO 避开冲突。

## 实测结果

| 组合 | 功能与压力测试 | 正常停服 |
| --- | --- | --- |
| ECO + Async + C2ME + Kotlin runtime，GameTest | 全部 2 个必需测试通过；包含完整压力流程 | `edb-shutdown-result.txt=PASS`；Gradle 成功 |
| lock 中全部 31 项依赖，同进程专用服 | `edb-test-result.txt=PASS`；包含 Carpet/additions、Lithium、VMP、ServerCore、Servux、地图、语音等 | `edb-shutdown-result.txt=PASS`；Gradle 成功 |

专用服使用独立新世界、loopback 随机端口，保持 `max-tick-time=10000`。两次日志中均没有原先的 `Clearing a borrowed collision table` 或 `Exception stopping the server`，没有发现原生内存段已关闭异常。Gradle 同时检查测试结果、停服标记与停服异常，未将“功能通过、停服失败”视为成功。

覆盖范围：

- 256 个已加载区块、1,024 个实体，五轮备份/修改/恢复；验证实体重新创建、内容恢复和每块实体查询结果。
- 10,000 个有数据的未加载区块，恢复后逐块核对标记并确认没有生成 holder；另有缺失区块删除测试。
- Async 后台任务屏障、并发方块事件队列，以及已有的光照、计划刻、方块实体与 C2ME 存储错误探针。
- 完整组合中的 Carpet 假人状态与载具挂载、区域交互和权限检查。
- 维护期间世界时间与游戏 tick 回调不推进；连接维护频率受限。专用服恢复后 10 tick 实测 500 ms。

专用服实测：10,000 区块备份 **18,459 ms**、恢复 **8,885 ms**；256 区块五轮备份为 573–717 ms，恢复为 381–609 ms。压力 CSV 中最长维护帧 20 ms。该轮用于合装回归，不是证明 Async 加速收益的 A/B 测试。

## 日志与结论边界

日志不是零 ERROR：包含故意构造的预览失效、非法坐标、玩家/编辑任务拒绝和 C2ME 存储失败场景；此外有 Windows 性能计数器、测试世界生成配置及 Mixin audit 的 `ClassAlreadyLoadedException` 消息。后者在此前 Async+C2ME 不含 ECO 的基线也存在，不能称本轮 Mixin audit 毫无告警。维护暂停时 spark 有等待世界统计超时的提示。这些没有导致本轮功能或停服检查失败。

结论为 **alpha.12 已通过当前锁定配置和 EDB 测试场景的合装回归，旧停服异常未复现**。没有恢复 EDB 的临时补丁，也没有重新加入检查 ECO 内部借用计数的探针。本轮每种组合各运行一次；不据此承诺长期所有并发时序、任意实体模组、Async 异步随机刻或真实多人网络负载均兼容。
